SpeakX Intelligent Notifications

A Self-Learning Orchestrator using K-Means, LLMs, and UCB1 Exploration

Replacing static, rule-based campaigns with an autonomous learning engine to drive habit formation for users transitioning to confident English speakers.

Explore the Project

The Core Problem

Static, rule-based push notifications suffer from severe limitations. We needed an engine capable of adapting and learning.

Key Vulnerabilities Addressed

  • The Segmentation Deficit: Static campaigns blast the same message. We built MECE segments mapping directly to distinct user motivations (e.g., Gamification vs. AI Tutors).
  • The Learning Bottleneck: Rule-based systems don't adapt. We needed an autonomous loop capable of classifying performance and aggressively exploring new variants while exploiting high performers.

Phase 1: Ingestion & K-Means Segmentation

Completely automating the clustering of raw user telemetry into actionable lifecycle profiles.

Ingestion Pipeline

Validates raw user CSV data, applying KNN-Imputation for missing values, engineering behavioral features (sessions, streaks), and scoring activeness/propensity mathematically.

Algorithmic Clustering

Implemented K-Means Clustering ($k=8$) validated by Decision Tree rules to partition users based on demographics, tier-city context, and feature usage.

Goal Mapping

Leveraging Gemini 2.5 Flash, the goal_builder module reads the segments alongside an ingested Markdown Knowledge Bank to dynamically generate day-on-day engagement goals mapped to the Trial vs. Paid lifecycle.

Phase 2: Theme Engine & Bilingual Templates

The Octalysis Hook System

Utilizes the 8 Core Drives of the Octalysis Framework (e.g., Epic Meaning, Loss Avoidance, Scarcity) to power the theme and template generation.

  • Dynamic Generation: The LLM creates exactly 5 distinct, bilingual (Hindi + English) templates per Segment $\times$ Time Unit $\times$ Theme.
  • Paced Schedules: Schedules 3-9 notifications daily across 6 standard time windows based on user activeness scores, deploying strict guardrails (reducing frequency if uninstall rate $> 2\%$).
Python LLM (Gemini) Octalysis Framework

Phase 3: The Autonomous Learning Engine

Bridging the gap between static campaigns and an AI agent using reinforcement learning heuristics.

Exploration vs. Exploitation via UCB1

Templates are classified into three buckets: GOOD (CTR $> 15\%$), NEUTRAL, and BAD (CTR $< 5\%$). Modeled as a Multi-Armed Bandit problem using the Upper Confidence Bound algorithm.

$$ \text{UCB}_j = \bar{X}_j + c \sqrt{\frac{\ln n}{n_j}} $$
Where $\bar{X}_j$ is the engagement score, and $c=0.15$

BAD templates are immediately suppressed ($\text{UCB} = -1$) and rewritten fresh by Gemini. Optimal delivery timing is updated dynamically using an Exponential Moving Average (EMA) with $\alpha = 0.70$.

The Final Architecture

Fully orchestrated through a single Python entry point managing over 50 LLM calls sequentially.
